# Salon AI

Дипломный проект: AI-система управления салоном красоты и обслуживания клиентов.
Интерфейс на туркменском, русском и английском языках.

## Возможности

**Для клиента:** каталог услуг, онлайн-запись, личный кабинет с отменой записи, чат-ассистент для записи, AI-анализ фото ногтей.

**Для мастера:** своё расписание и отметка статуса визита.

**Для администратора:** аналитика, прогноз спроса, расписание всех мастеров, запись клиента по телефону, управление услугами, мастерами и их графиком, база клиентов.

## Запуск

Нужны Node.js, Python 3.12+ и запущенный PostgreSQL.

```bash
createdb salon_ai

cd backend
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
cp .env.example .env                 # укажите JWT_SECRET
.venv/bin/alembic upgrade head
.venv/bin/python -m app.seed         # демо-данные; --reset пересоздаёт их
.venv/bin/uvicorn app.main:app --port 8000
```

Во втором терминале:

```bash
cd frontend
npm install
npm run dev
```

Приложение: http://localhost:5173. Документация API: http://localhost:8000/docs.

### Подключение AI

Чат и анализ фото работают только с ключом. Создайте его на https://platform.claude.com, пополните баланс и укажите в `backend/.env`:

```
ANTHROPIC_API_KEY=ваш-ключ
```

После этого перезапустите сервер. Без ключа остальное приложение, включая прогноз спроса, работает как обычно.

## Архитектура

```
Браузер (React) ──/api──> FastAPI ──> PostgreSQL
                            │
                            ├─ services/booking.py    свободные окна и создание записи
                            ├─ services/forecast.py   ML-модель прогноза
                            ├─ services/analytics.py  показатели и подготовка данных
                            ├─ services/assistant.py  чат: цикл Claude с инструментами
                            └─ services/nails.py      анализ фото через Claude
```

Основные решения, которые стоит объяснить на защите:

- **Защита от двойной записи.** Ограничение `no_master_overlap` в PostgreSQL не даёт пересечься двум записям одного мастера, даже при одновременных запросах. Проверка только в коде этого не гарантирует.
- **Единая логика записи.** Сайт и чат-ассистент вызывают один и тот же код из `booking.py`, поэтому у модели нет способа обойти правила.
- **Безопасность ассистента.** Клиент определяется по сессии, а не по параметру инструмента, поэтому модель не может действовать от имени другого человека, даже если её об этом попросят. Перед записью ассистент должен получить подтверждение клиента.
- **Анализ фото.** Ответ модели проверяется по JSON-схеме, а рекомендации сверяются с каталогом. Сами фото на сервере не хранятся, но отправляются в Claude API.
- **Роли.** Права проверяются на сервере; регистрация всегда создаёт только клиента.

## Прогноз спроса

Модель: `GradientBoostingRegressor`. Признаки: день недели, сезонность, тренд, значения 7, 14 и 28 дней назад, скользящие средние за 7 и 28 дней. Прогноз многошаговый: предсказанные значения становятся входом для следующих дней.

Качество проверяется на последних 28 днях, которых модель не видела, в сравнении с базовым прогнозом «как неделю назад» (метрики MAE, RMSE, wMAPE). Результаты показаны в разделе «Аналитика».

**Важно для текста диплома:** демо-история сгенерирована скриптом `app/seed.py`, в ней заложены недельный цикл, тренд, сезонность и случайный шум. Метрики на этих данных показывают, что метод работает, но не являются результатом реального салона. Так и укажите в работе, а по возможности проверьте модель на настоящих данных.

## Перед использованием

- Туркменские тексты (`frontend/src/locales/tk.ts` и услуги в `backend/app/seed.py`) написаны без участия носителя языка: их нужно вычитать.
- Даты в демо-истории привязаны к дню запуска: выполните `python -m app.seed --reset` незадолго до защиты. Команда удаляет все данные.
- Демо-пароли и `JWT_SECRET` нужно заменить, если приложение будет доступно из интернета.

## Ограничения

- Лимиты запросов хранятся в памяти одного процесса и сбрасываются при перезапуске.
- Нет онлайн-оплаты и уведомлений по SMS или почте.
- Токен входа хранится в `localStorage`. Для реальной работы лучше перейти на cookie с флагом `HttpOnly`.
- Модель прогноза обучается при каждом открытии аналитики: при годовой истории это занимает доли секунды.
